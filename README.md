# conformance testing

This repository runs upstream conformance test suites against pinned builds of
[Elide](https://elide.dev) and publishes per-version reports. Suites:

| Suite | What it covers |
|---|---|
| `test262` | TC39's JavaScript conformance suite |
| `wpt-wintertc` | a sparse Web Platform Tests subset for WinterTC / ECMA-429 APIs, including fetch |
| `cpython-core` | CPython 3.12 `Lib/test/test_*` modules and packages |
| `javac-jtreg` | OpenJDK langtools `tools/javac` through jtreg, compiling with Elide |
| `node-api` | sparse Node.js core JavaScript API tests |

[Bali](BALI.md) is also supported as a Docker-based runtime target; see
[running](docs/running.md#bali-runtime-target).

Tracking: [Compliance Testing meta (WHIPLASH#1172)](https://github.com/elide-dev/WHIPLASH/issues/1172),
[Test262 (WHIPLASH#1173)](https://github.com/elide-dev/WHIPLASH/issues/1173).

## How it works

A Bun/TypeScript harness drives each suite through its best native runner and
normalizes the results. Each run executes inside a Docker image with a pinned
Elide, so every `elide run` is a fast local subprocess. Results are compared
against a checked-in expectations baseline: new failures are regressions, tests
that newly pass advance the floor, and a `--ratchet` run locks the gains in.

Skips never inflate the numbers above: a skipped test still counts as a non-pass
in _Pass rate_. Every skip has a written reason in `expectations/<suite>.toml`;
see [why tests are skipped](docs/reports.md#why-tests-are-skipped).

## Quick start

```bash
bun run setup                                        # deps + suite submodules
bun run testsuite --elide nightly --suite test262 --log
bun run testsuite --elide nightly --all-suites --log
```
